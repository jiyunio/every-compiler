# every compiler

GitHub Pages에 그대로 올릴 수 있는 HTML/CSS/JavaScript Java 편집기입니다. 빌드 과정이나 API 키가 필요하지 않습니다.

## 배포

1. GitHub 저장소를 만들고 이 폴더 안의 `index.html`, `style.css`, `app.js`, `.nojekyll`을 저장소 루트에 업로드합니다.
2. 저장소의 Settings → Pages에서 Source를 **Deploy from a branch**로 선택합니다.
3. Branch를 **main**, 폴더를 **/(root)**로 선택하고 저장합니다.
4. 배포 완료 후 Pages에 표시되는 주소로 접속합니다. 프로젝트 저장소의 하위 경로에서도 작동합니다.

## 사용

- 실행: 실행 버튼 또는 Ctrl+Enter (Mac: Cmd+Enter)
- 입력: 실행 전에 프로그램 입력에 Scanner 등에서 읽을 값을 입력합니다. 실행 도중 대화형 입력은 지원하지 않습니다.
- 하나의 Java 코드 영역에서 작성하며, Main 클래스가 시작점입니다. 여러 클래스는 같은 코드 영역 안에 작성할 수 있습니다.
- 창 접기: 입출력 제목 옆 화살표. 입력만 접을 수도 있습니다.
- 크기 조절: 편집기와 입출력 사이 경계를 드래그합니다. 키보드는 경계에 Tab으로 이동한 뒤 방향키를 사용합니다.
- 집중 모드: 입출력 창을 숨겨 편집기를 확장합니다. Esc로 복귀합니다.
- 라이트/다크: 오른쪽 위 버튼. 테마만 브라우저에 저장합니다.
- 파일과 코드는 메모리에만 있으며 새로고침하면 기본 코드로 돌아옵니다.

## 실제 Java 실행과 제한

GitHub Pages는 정적 호스팅이므로 Java 실행은 외부 **Wandbox 공개 API** (`https://wandbox.org/api/`)에서 처리합니다. 실행할 때 Java 코드와 입력이 전송됩니다. 저장 링크 생성은 요청하지 않습니다(`save: false`). 개인정보나 비밀 키를 입력하지 마세요.

컴파일러 목록에서 사용 가능한 Java 버전을 선택합니다. API의 가용성, 브라우저 CORS 허용, 사용량 제한과 실행 시간/메모리 제한에 영향을 받습니다. 연결 실패 시 실제 오류를 표시하며 가짜 실행 결과를 출력하지 않습니다. 요청은 45초 후 중단하지만 원격 실행을 취소하는 것은 아닙니다. 컴파일 오류와 프로그램 출력은 각각 그대로 표시합니다.

이 제작 환경에서는 Wandbox 접속이 차단되어 **실제 원격 Java 실행은 검증하지 못했습니다**. 배포 후 아래 항목을 확인하세요. 운영 서비스에서 안정적인 실행이 필요하면 별도의 Java 샌드박스 실행 서버를 연결해야 합니다. GitHub Pages에 비밀 API 키를 넣으면 안 됩니다.

검증 예시:
1. 기본 코드 → `Hello world!`
2. `Scanner`로 두 정수를 읽어 합 출력 + 입력 `10 20` → `30`
4. 세미콜론 누락 → 컴파일 오류
5. 무한 루프 → 실행 서비스 제한 또는 요청 시간 초과

폰트는 Google Fonts에서 불러오며 연결되지 않아도 시스템 폰트로 표시됩니다. 편집기는 외부 편집기 라이브러리 없이 구문 색상, 줄 번호, Tab 들여쓰기를 지원합니다.
